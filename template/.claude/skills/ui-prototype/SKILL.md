---
name: ui-prototype
description: 在任何视觉改动（CSS、布局、颜色、间距、动效、组件外观）之前使用。先在 docs/02-design/prototypes/ 做一个可直接打开的 HTML 原型，然后停下来等用户确认，确认前不改 web/src 里的样式。
when_to_use: 用户说“改一下样式/颜色/布局/好看点/调 UI/做个新页面外观”时
argument-hint: "[原型名，例如 v2.9-quiz-card]"
---
最重要：**原型被用户明确确认之前，不修改 web/src/ 下任何样式代码。**

1. 读当前相关组件，找出要改的视觉部分；列出“改什么 / 不改什么”。
2. 新建 `docs/02-design/prototypes/$ARGUMENTS.html`（没给名字就用 `v<下一个版本号>-<主题>.html`）：
   - 单文件，内联 CSS，不引外部依赖，手机宽度（375px）优先
   - 如有前后对比，左右或上下并排展示“现在 / 提议”
3. 在回复里给出：原型文件路径、改动要点（3–5 条）、需要用户拍板的问题。
4. **停下，等待用户回复“确认”**。用户要求修改就迭代原型，不要动源码。
5. 用户确认后，才按原型修改源码，并在 PR 描述里链接原型文件。
